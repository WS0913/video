图4-3 设备注册流程图
sequenceDiagram
    participant Client as 摄像头采集端
    participant Backend as FastAPI 后端
    participant DB as 数据库

    Client->>Client: 读取配置
(设备名称、类型、位置)
    Client->>Client: 获取本机 IP 地址
    Client->>Backend: POST /api/devices/register
(设备信息 + IP)
    Backend->>DB: 根据 IP 查询设备

    alt 设备已存在
        Backend->>DB: 更新设备信息和状态
        Backend-->>Client: 返回已有 device_id
    else 设备不存在
        Backend->>Backend: 生成唯一 device_id
        Backend->>Backend: 构造流地址
(基于 device_id)
        Backend->>DB: 创建新设备记录
        Backend-->>Client: 返回 device_id 和 stream_url
    end

    Client->>Client: 保存 device_id
    Client->>Client: 启动心跳线程
    Client->>Client: 启动推流模块

图4-4 心跳检测与状态更新流程图
sequenceDiagram
    participant Client as 摄像头采集端
    participant Backend as FastAPI 后端
    participant Monitor as 设备监控服务
    participant DB as 数据库

    loop 每隔固定时间间隔
        Client->>Backend: POST /api/devices/{id}/heartbeat
(timestamp + 网络指标)
        Backend->>DB: 更新 last_heartbeat 和 status=online
        Backend-->>Client: 200 OK
    end

    loop 后台监控任务每隔 6 秒
        Monitor->>DB: 查询所有 status=online 的设备
        Monitor->>Monitor: 检查 last_heartbeat 是否超时

        alt 发现超时设备
            Monitor->>DB: 更新 status=offline
            Monitor->>Monitor: 记录日志
        end
    end

    Note over Client,DB: 前端刷新设备列表时
可看到最新在线状态
